# ebpf

Loads eBPF programs from Go with `github.com/cilium/ebpf` and attaches an XDP program to a network interface. A second program, an `execve` tracepoint tracer, is compiled but its loading code is commented out.

## What the code does

- `bpf/packet.c` (XDP, section `xdp`): for every incoming frame, it checks that a full Ethernet header fits and calls `bpf_printk("XDP: ethernet packet")`. If the EtherType is IPv4, it also prints `"XDP: IPv4 packet"`. It always returns `XDP_PASS`, so no traffic is dropped.
- `bpf/tracker.c` (tracepoint `syscalls/sys_enter_execve`): logs the PID and command name of every `execve` with `bpf_trace_printk`.
- `bpf_bpfel.go`/`bpf_bpfeb.go` (+ `.o`) and `packet_bpfel.go`/`packet_bpfeb.go` (+ `.o`): **generated by bpf2go** from `bpf/tracker.c` and `bpf/packet.c`, for little- and big-endian targets. Don't edit them by hand.
- `main.go`:
  1. Looks up the interface named **`wlan0`** and loads the packet objects.
  2. Attaches `PacketFilter` with `link.AttachXDP` and prints three status lines.
  3. Waits for SIGINT or SIGTERM, then detaches and closes everything with `defer`.

  The tracker load and `link.Tracepoint` code is commented out.

The `bpf_printk` output goes to the kernel trace buffer, not stdout. You can read it with `sudo cat /sys/kernel/debug/tracing/trace_pipe`.

## Concepts you can learn

- **The bpf2go workflow**: `//go:generate bpf2go ...` compiles C to BPF bytecode with clang and generates Go bindings (`loadPacketObjects`, typed `packetObjects`) with the `.o` file embedded. The result is a single static Go binary.
- **XDP**: the program runs in the NIC driver path before the kernel network stack, which makes it the earliest and cheapest place to inspect or drop packets. It returns `XDP_PASS`, `XDP_DROP`, and similar verdicts.
- **Bounds checks for the verifier**: `if ((void *)(eth + 1) > data_end)` is required. Without it, the kernel verifier rejects the program.
- **Tracepoints**: stable kernel hook points (such as `sys_enter_execve`) for observing syscalls.
- **Link lifetime**: closing the `link` (or exiting the process) detaches the program.

## How to run

**Linux only.** You need root privileges (or `CAP_BPF` + `CAP_NET_ADMIN`) and an interface named `wlan0`.

```bash
cd ebpf
sudo go run .
# in another terminal:
sudo cat /sys/kernel/debug/tracing/trace_pipe
```

To regenerate the bindings after editing the C files, you need clang, the libbpf headers (`bpf/bpf_helpers.h`), and the `bpf2go` tool on `PATH`:

```bash
go install github.com/cilium/ebpf/cmd/bpf2go@v0.22.0   # same version as go.mod
cd ebpf
go generate
```

The `-I/usr/include/x86_64-linux-gnu` flag in the generate directive assumes an x86_64 Debian/Ubuntu layout.

On Windows, `go build` fails with `undefined: link.AttachXDP` because that API exists only on Linux; the topic wasn't run.

## Notes

- The interface name `wlan0` is hard-coded. Change it in `main.go` if your NIC has another name (for example, `eth0` or `enp0s3`).
- `main` prints `process tracing: syscalls/sys_enter_execve` even though the tracepoint program is never loaded. That line is misleading.
- `bpf_printk` runs on every packet, which is noisy and slow on a busy interface.
- `tracker.c` begins with a `// +build ignore` comment.
